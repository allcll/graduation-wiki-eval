# C에서 Skill을 실제로 읽는지 확인하기

2026-11-15, 같은 문의를 C 조건에서 두 번 실행했습니다. **기존 C는 WIKI만 읽고 6학점으로 답했고, Skill 읽기와 확인 절차를 보완한 C는 9학점으로 답했습니다.** 다만 두 실행 모두 편람을 읽거나 검색한 기록이 없었습니다. 수치 일치와 근거 검증을 구분해서 남깁니다.

## 먼저 확인한 문제

이전에는 Skill 본문을 빠짐없이 제공했는지만 검사했습니다. 어댑터는 모델에게 관련 문서를 선택해서 읽도록 안내했고, 실제로 읽었는지는 확인하지 않았습니다.

이번에는 기존 Skill 그대로 실행하면서 Claude Code의 도구 이벤트를 기록했습니다. 결과는 다음과 같았습니다.

1. `cohort/2022/balance.md` 전체 70줄을 읽음
2. `INDEX.md` 전체 147줄을 읽음
3. Skill·편람의 Read 또는 검색 기록 없이 6학점으로 답함

따라서 이 실행을 ‘Skill의 WIKI 우선 지침을 읽고 따랐기 때문에 틀렸다’고 설명할 수 없습니다. 확인된 문제는 **파일 목록을 제공한 것만으로 Skill을 활용했다고 가정한 점**입니다. 학점 최소 기준을 상한으로 오해한 최종 답변도 그대로 보존했습니다.

## 보완한 내용

- `--trace-tools`: 도구 요청과 결과를 연결하고, 실제 반환된 파일·줄 범위와 성공 여부를 기록합니다. 검색·부분 읽기·실패·미완료를 구분하며 원문 내용이나 사고 과정은 기록에 복사하지 않습니다.
- `--require-skill-reads`: 지정한 Skill 관련 파일을 모두 Read로 읽도록 지시합니다. 전체 줄 범위가 확인되지 않으면 정상 응답으로 처리하지 않습니다. 네이티브 Skill 자동 발동 기능은 아닙니다.
- [query 확인 절차](skills/query-verification.md): 지정 판본의 원문 대조, 적용 대상과 예외 확인, 영역 수·이수 학점 합계·최소 기준 분리, 명시된 근거가 있을 때만 상한 적용, 실제 확인한 원문 인용을 추가했습니다.

질문·입력 정의·정답·채점 기준은 `pilots/cs-001-v2` 그대로 사용했습니다. 원문과 WIKI도 바꾸지 않았습니다. 컨텍스트 파일 중 바뀐 것은 평가용 복사본의 query Skill 본문 한 파일이며, 그 안에서도 `## 절차` 부분만 교체했습니다. wrapper·CLAUDE.md·PROJECT.md·기존 가드레일은 그대로입니다. WIKI 원본 레포에는 수정하지 않았습니다.

첫 관찰에서 Skill을 읽지 않는 문제가 드러나 후속 실행에 읽기 지시와 검사를 추가했습니다. 따라서 이번 변경은 **읽기 적용과 절차 보완의 결합**입니다. Skill 문구만의 독립적인 효과로 해석하지 않습니다.

보완한 실행에서는 wrapper 11줄, CLAUDE.md 35줄, PROJECT.md 74줄, 수정된 query 본문 21줄을 모두 읽은 뒤 WIKI를 읽었습니다. 인정 영역 2개, 이수 합계 9학점, 필요 영역 2개, 필요 학점 6, 충족 여부 true로 답해 정답의 값과 일치했습니다.

하지만 **절차 전체를 따르지는 않았습니다.** 본문에 원문 대조 절차를 추가했는데도 2026-2 편람의 Read·검색은 없었고, 최종 답변은 `2026-1 p.52` WIKI와 Skill의 계산 지침을 인용했습니다. Skill 지침은 정책 수치의 원출처를 대신하지 않습니다. 현재 시스템의 집계 원인을 추정하는 설명도 남아 있어 검토가 필요합니다.

이번 기록은 ‘본문이 제공됨 → 본문을 읽음 → 지침을 수행함 → 답과 근거가 맞음’이 각각 별도의 확인 대상임을 보여줍니다. 읽기 검사 통과를 답변 품질 PASS로 사용하지 않습니다.

## 고정한 조건과 남은 한계

- 문항: `CS-2026-2-001`, `pilots/cs-001-v2`, 각 실행 C 1회
- 요청 모델 `claude-sonnet-4-6`, Claude Code 2.1.325, effort medium, 최대 12턴·180초, 실행기 210초
- 기존 Claude Pro 로그인 사용. 사용자가 추가 사용량을 껐다고 확인했으며 API 키·별도 과금 경로로 우회하지 않음
- 편람·WIKI의 파일 경로와 해시, 질문·정답·rubric 해시 동일
- WIKI 커밋 `b7d05fcae2c8f588b2ed18e0fa4bc4f87d23512a` 유지

후속 실행에는 `--require-skill-reads`의 지시가 추가됐으므로 전체 모델 프롬프트가 동일한 실험은 아닙니다. 요청 JSON의 공통 지시와 질문은 유지했지만 어댑터 지시와 Skill 절차를 함께 바꿨습니다. 각 조건 1회로 일반적인 개선율이나 속도 향상을 주장하지 않습니다.

수정 문항과 모델 답변의 사람 검토는 대기 중이며, 독립 holdout도 없습니다. 자동 비교·품질 gate는 `INCONCLUSIVE`입니다. 다음 확인 대상은 원문 읽기와 지정 판본의 근거 제시입니다. 지침을 적는 것과 수행을 검증하는 것을 구분한 뒤, 별도 QA 작업 평가로 넓힐 수 있습니다.

## 다시 실행할 때

[CS-001 준비 절차](../../datasets/graduation-2026-2/pilots/cs-001-v2/README.md)의 원문·WIKI·Skill 자료를 별도 컨텍스트 폴더 두 개에 복사합니다. 두 설정 모두 `conditions: ["C"]`, 같은 문항과 실행 제한을 사용합니다. 첫 번째는 기존 Skill, 두 번째는 query 본문의 `## 절차`부터 `## 가드레일` 직전까지를 [수정 절차](skills/query-verification.md)로 교체합니다. 다른 파일과 질문을 함께 바꾸지 않습니다.

`model_config`에는 첫 번째에 `trace-tools=on`, 두 번째에 `trace-tools=on;require-skill-reads=on`을 기록합니다. 각각 `prepare`로 새 계획을 만든 뒤 첫 번째는 아래 명령에서 `--require-skill-reads`를 빼고, 두 번째는 포함해 실행합니다. `run`부터 실제 모델이 호출됩니다.

```sh
node dist/cli.js run --plan artifacts/your-new-c-plan/plan.json -- \
  node "$PWD/dist/adapters/claude.js" --auth subscription --usage-credits-disabled \
  --trace-tools --require-skill-reads --model claude-sonnet-4-6 \
  --max-turns 12 --effort medium --timeout 180
```

파일별 읽기 기록의 해석은 [모델 연결 가이드](../adapters.md#실제-파일-읽기-기록)를 따릅니다. 처음부터 두 실행에 읽기 검사를 동일하게 켜고 기존·수정 Skill을 비교하면 읽기 적용과 문구 변경의 영향을 더 좁혀볼 수 있습니다. 이번 작업에서는 위 2회만 호출하고 추가 반복은 하지 않았습니다.
