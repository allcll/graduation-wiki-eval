# CS-2026-2-001: 9학점과 6학점의 차이

2026-11-15 Codex가 최초 실행의 원문·입력 스냅샷·최종 답변을 대조한 기록입니다. 모델을 재호출하지 않았고, 사람의 검토 기록이나 최초 응답·정답 파일을 수정하지 않았습니다.

## 정답지 확인

이 사례에서 구분해야 할 값은 다음과 같습니다.

| 값 | 의미 | 판단 |
| --- | --- | --- |
| 9학점 | 질문에 제시된 세 과목의 이수 학점 합계 | `recognized_credits`가 실제 이수 합계라는 의도라면 유지 |
| 6학점 | 2022학번 균형교양의 필요 학점 | `required_credits` |
| 3학점 | 문의 당시 화면에 표시됐다는 값 | 질문의 문제 상황이며 규정상 정답이 아님 |

[세종대학교가 공개한 2026-2 수강편람](https://www.sejong.ac.kr/kor/intro/notice3.do?articleNo=891086&mode=view)의 52쪽 졸업 기준과 53쪽 §4는 소속 계열과 다른 2개 영역에서 6학점을 선택 이수하도록 정합니다. 53쪽 표와 각주를 이미지로 확인하고, 병합셀은 pdfplumber `find_tables()`로 대조했습니다.

| 과목 | 영역 | 편람 표의 학점 | 경영경제 계열 제외 여부 |
| --- | --- | ---: | --- |
| 현대과학으로의초대 | 자연과과학 | 3 | 제외되지 않음 |
| 현대예술의이해 | 문화와예술 | 3 | 제외되지 않음 |
| 한국의문화와한류 | 문화와예술 | 3 | 제외되지 않음 |

따라서 제시된 이수 조건에서는 **2개 영역, 이수 합계 9학점, 필요 기준 6학점, 충족**으로 계산합니다. 문화와예술 두 과목은 영역 수에서는 하나로 세지만, 그것만으로 과목 하나의 학점이 사라지지는 않습니다. 확인한 표·각주에는 영역별 인정 상한 3학점이나 초과 과목을 교양선택으로 전환한다는 규정이 없습니다. 9는 편람이 이 사례의 답으로 직접 제시한 수치가 아니라, 적용 대상과 과목별 학점에 질문의 이수 조건을 대입한 계산값입니다.

구현도 별도로 대조했습니다. [백엔드의 균형교양 계산](https://github.com/allcll/allcll-backend/blob/344229e69f0d5380e853e7ec5a7c3e9f0ad68ffe/src/main/java/kr/allcll/backend/domain/graduation/check/result/CategoryCreditCalculator.java#L187)은 `BALANCE_REQUIRED` 이수 과목의 학점을 합산하고 `earnedCredits >= requiredCredits`를 검사합니다. 6학점으로 잘라 저장하거나 영역마다 3학점으로 제한하지 않습니다. [화면의 이수 학점 표시](https://github.com/allcll/allcll-frontend/blob/40493ebd0389a43d3512857beb7ca010e9f74f2c/packages/common/src/components/graduation/CategoryProgressCard.tsx#L35)도 두 값을 나란히 표시합니다. 세 과목이 해당 이수구분으로 들어온다는 전제의 구현 확인이며, 운영 DB를 새로 조회하거나 신고 당시 배포본을 재실행한 검증은 아닙니다. 구현 자체를 편람 규정의 정답 근거로 대신하지 않았습니다.

## B/C 답변에서 확인한 오류

B는 같은 영역의 두 번째 과목이 추가 인정되지 않으며 교양선택 등으로 처리된다고 설명했습니다. C는 영역당 3학점만 반영해 나머지를 요건 초과분으로 설명하고 `recognized_credits`를 6으로 반환했습니다. 두 응답 모두 충족에 필요한 기준을 이수 합계의 상한처럼 사용했습니다.

WIKI에는 2개 영역에서 각 3학점, 총 6학점을 이수한다는 요약이 있지만, **최대 3학점만 인정한다는 문장은 없습니다.** B/C가 덧붙인 상한과 이수구분 전환은 제공된 근거에서 확인되지 않습니다.

다음은 영향을 줬을 가능성이 있는 요소이며, 반복 실험으로 확정한 인과관계는 아닙니다.

- WIKI의 간결한 6학점 요약에 인정 학점 합계와 필요 학점의 차이가 설명돼 있지 않습니다. 원문을 대조하지 않고 요약을 상한으로 확대 해석했을 가능성이 있습니다.
- 문항의 `recognized_credits` 설명이 ‘이수 과목 중 인정 학점’으로만 되어 있어 실제 이수 합계와 최소 충족에 사용할 학점을 혼동하기 쉽습니다. 필드 이름과 정의는 평가셋 쪽에서도 보완해야 합니다.
- B/C의 최종 인용은 WIKI에 집중됐고 B는 2026-1 근거를 사용했습니다. 2026-2 원문을 대조했다는 증거가 최종 답변에 충분히 남지 않았습니다. 도구 호출 추적을 저장하지 않았으므로 실제로 원문을 전혀 읽지 않았다고 단정하지는 않습니다.

## C 조건은 Skill 본문이 누락됨

첫 실행에 넣은 `.claude/skills/grad-wiki-query/SKILL.md`는 10줄짜리 연결 파일입니다. 실제 절차는 `docs/agent-harness/skills/grad-wiki-query/SKILL.md`에 있고, 연결 파일은 `@../../../docs/agent-harness/skills/grad-wiki-query/SKILL.md`로 이를 가리킵니다.

그런데 C 스냅샷에는 연결 파일만 있고 본문은 없습니다. 어댑터는 네이티브 Skill·슬래시 명령을 끄고 명시된 파일을 문서로만 읽게 하므로 이 참조를 자동으로 가져오지 않습니다. 참조한 대상도 실행 디렉터리에 존재하지 않습니다.

이는 **평가 입력을 구성한 Codex의 누락**입니다. 최초 C를 ‘정상적인 Skill 문서 제공 결과’로 설명한 것을 정정합니다. 요청이 성공했고 JSON이 반환됐다는 사실과 실험 조건이 제대로 구성됐다는 사실은 별개입니다. C 결과는 입력 구성 실패 기록으로 보존하고 Skill 효과 비교에서는 제외해야 합니다.

현재 `prepare`는 C에 Skill 파일이 하나 이상 있는지, 파일 경로와 해시가 맞는지 검사합니다. 절차 본문 및 참조 의존성이 빠졌는지 확인하는 검사는 없습니다. 소프트웨어 테스트 통과만으로 이번 입력 구성이 유효하다고 판단할 수 없었습니다.

## 다음 조치

1. 정답값 9를 모델 답변에 맞춰 6으로 변경하지 않습니다. 실제 이수 합계와 필요 기준을 구분하도록 입력 필드 정의를 보완하고, 사람이 편람과 함께 검토합니다. 입력 정의가 바뀌면 사례 버전·해시를 갱신해야 합니다.
2. C에는 wrapper 대신 실제 절차 본문과 필요한 참조 파일을 명시적으로 제공합니다. 제공한 문서가 요구하는 도구와 실제 허용 도구의 차이도 기록합니다. 이것만으로 네이티브 Skill 실행 평가가 되는 것은 아닙니다.
3. 준비 단계에서 본문이 없는 wrapper와 끊어진 참조를 호출 전에 찾아 중단하는 검사를 추가합니다. 원문·WIKI·Skill의 역할 및 실제 사용한 근거도 추적할 수 있어야 합니다.
4. 입력 정의와 C 구성 보완을 기록한 새 계획으로 비교합니다. WIKI 효과를 확인하려면 이 변경과 WIKI 문구 수정 실험을 구분하고, 같은 조건에서 반복해 확인합니다.

이번 변경은 분석 기록과 기존 결과 설명의 정정입니다. 평가 실행기·WIKI·112건 정답지에는 아직 위 보완을 적용하지 않았습니다. 원본 계획·응답·자동 보고서를 그대로 유지하고, 사람 검토는 대기 상태로 둡니다.
