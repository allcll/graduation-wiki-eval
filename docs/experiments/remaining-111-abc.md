# 남은 111건의 A/B/C 평가

2026-11-15에 남은 111건의 A/B/C 평가를 시작했습니다. CS-2026-2-001은 기존 응답을 보존하고 이번 실행에서 제외했습니다. 46개 답변을 수집한 뒤 47번째 요청이 Claude의 5시간 구독 한도로 차단되어 중단했습니다. **333회 전체 평가를 완료한 결과가 아닙니다.**

## 수집한 결과

| 구분 | 건수 |
| --- | ---: |
| 계획 | 111사례 × 3조건 = 333회 |
| 모델 답변 확보 | 46회 |
| 구독 한도로 답변 없이 차단 | 1회 |
| 아직 호출하지 않은 작업 | 286회 |
| A/B/C 답변을 모두 확보한 사례 | 15사례 |
| 전체 계획의 답변을 채우려면 필요한 작업 | 차단 1회 재실행 + 미실행 286회 = 287회 |

처음에는 일반 서비스 오류로 기록되어 실행을 중단했습니다. 이후 같은 구독 인증으로 수행한 별도의 연결 진단에서 `You've hit your 5-hour limit` 응답을 확인했습니다. 당시 표시된 초기화 시각은 2026-11-15 15:50(한국 시간)입니다. 기존 오류 기록을 덮어쓰지 않고 중단 원인을 추가 기록했으며, API 키나 추가 과금 경로로 전환하지 않았습니다. 연결 진단은 평가 결과에 포함하지 않았습니다.

다음은 A/B/C 답변이 모두 있는 **동일한 15사례**만 비교한 값입니다.

| 조건 | action·facts 정답값 일치 | 편람 읽기·인용 검사 통과 | 어댑터가 정상 응답으로 채택 |
| --- | ---: | ---: | ---: |
| A | 14/15 | 2/15 | 2/15 |
| B | 14/15 | 2/15 | 2/15 |
| C | 13/15 | 2/15 | 1/15 |

이 표는 최종 품질 통과율이 아닙니다. 정답값 비교에는 인용 검사에서 거절된 후보 응답도 포함했습니다. C에서는 인용을 통과했어도 필수 Skill 파일을 모두 읽지 않아 채택하지 않은 응답이 있습니다. 사람의 본문·근거 해석 검토는 모두 대기 상태입니다.

- CS-2026-2-002: A/B의 정답 필드는 일치했지만, A의 본문에는 추가 제외영역을 주장하는 내용이 있었습니다. 필드 일치만으로 본문까지 정확하다고 볼 수 없습니다.
- CS-2026-2-011: A/B의 정답 필드는 불일치하고 C는 일치했습니다. A는 인용 자체는 통과했으나 기대한 규정과 다른 조항을 적용한 것으로 보여, 적용 대상과 정답지 해석을 함께 재검토해야 합니다.
- CS-2026-2-015: 세 조건 모두 정답 필드와 인용 검사를 통과했습니다. 이 경우에도 사람 검토를 완료한 것으로 표시하지 않았습니다.

실행 순서상 앞부분의 CS 사례만 수집된 상태이므로, 이를 영어·고전독서·코딩·전공 요건 전체의 성능으로 일반화하지 않습니다. [기계 판정과 응답 해시](remaining-111-abc.observations.json)를 함께 남겼습니다. 저장된 후보 답변으로 인용 검사기를 다시 확인할 수 있으며, 검사기 개선 결과와 모델 답변 개선 결과는 구분해야 합니다.

기존 보고서의 `synthetic` 표시는 문항의 `origin`과 실행의 `execution`을 함께 사용합니다. 이번 계획에는 편람 기반 가상 문항 87건이 있어서 미실행 상태에서도 합성 표시가 나타납니다. **수집한 46개 답변은 실제 Claude 응답**이며, 이 표시를 고정 답변 데모로 실행했다는 뜻으로 해석하지 않습니다. 문항의 출처와 모델 실행 방식을 분리하는 보고서 개선은 별도로 필요합니다. 이번 기록에서는 기존 gate를 바꾸거나 검토 전 답변을 통과로 처리하지 않았습니다.

## 비교하려는 것

같은 질문에 편람만 제공했을 때(A), WIKI 정책 문서를 추가했을 때(B), query Skill 문서를 더했을 때(C)의 답변을 비교합니다. 하나의 사례를 맞힐 때마다 지침을 고치지 않고, 전체 실행 동안 조건을 고정합니다.

| 실행 수 | 111건 × A/B/C × 1회 = 333회 평가. 에이전트 내부 모델 요청 수와는 다름 |

다른 페이지의 표는 셀 문구를 각각 인용하도록 공통 지침에 명시했습니다. 인용 문구의 존재와 정책 해석의 정확성은 별도로 판단합니다. 53쪽 밖의 표에 대해서도 셀 관계를 자동 검증했다고 보고하지 않습니다.

## 제공 자료와 제외 자료

A에는 원문만, B에는 원문과 WIKI, C에는 원문과 WIKI·Skill을 제공합니다. 질문에 필요한 입력과 출력 필드 정의는 공통입니다. 정답값, Rubric, 정답지의 근거 발췌, 검토 상태, 과거 모델 응답은 전달하지 않습니다. WIKI의 CS 트리아지·감사 보고서와 학생 기록도 이번 제공 범위에 넣지 않았습니다.

WIKI 전체 저장소를 평가한 것이 아니라 위에 명시한 정책 문서 범위를 평가합니다. 네이티브 Skill 자동 선택은 비활성화되어 있으며, C는 Skill 문서를 제공하고 읽게 하는 조건입니다.

## 실행 전 확인

- 333개 요청의 질문·입력이 공개 평가셋의 해당 사례와 같고, 정답 관련 필드가 요청에 없는지 확인했습니다.
- 조건별 제공 파일 수가 A=원문 3개, B=A+WIKI 69개, C=B+Skill 4개인지 확인했습니다.

## 중단과 기록

실행은 사례별 A→B→C 순서입니다. 완료된 작업은 즉시 저장하고, 모델 오답·인용 검사 실패는 기록한 뒤 계속 진행합니다. 구독 한도·인증·서비스 오류는 로컬 실행 감독 코드가 확인해 이후 작업을 중단합니다. API 키 인증으로 전환하지 않습니다. 추가 사용량 OFF는 사용자의 기존 확인을 사용하며 실행기가 과금 설정을 조회한 것은 아닙니다.

`runPlan`의 `onRecord`는 결과 저장 후 중단할 수 있는 연결점입니다. 구독 오류 감지나 자동 재개 기능 자체는 아닙니다. 중단된 이후의 사례는 오답으로 집계하지 않고 미실행으로 남깁니다.

실제 요청, 답변, 읽기 이력, 인용 검사와 오류는 로컬 실행 폴더에 저장합니다. 인용 검사에서 탈락한 구조화 답변도 진단용 후보 응답으로 보존하며, 정상 응답으로 바꿔 집계하지 않습니다.
