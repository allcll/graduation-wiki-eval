# C가 지정 판본의 편람을 읽고 인용하는지 확인하기

2026-11-15, `CS-2026-2-001`을 C 조건에서 한 번 실행했습니다. **이번에는 2026-2 편람 PDF 51~53쪽을 읽었고, 이수 합계 9학점·최소 기준 6학점으로 답했습니다.** 다만 인용 6개 중 4개가 정해 둔 원문 문구 검사에 걸려 정상 응답으로 채택하지 않았습니다.

> 아래는 최초 `source-check-v1` 실행 기록입니다. 이후 기준을 보완해 저장 응답을 다시 검사한 결과는 [표 인용 재검사](cs-001-table-recheck.md)에 별도로 기록했습니다. 기존 응답·검사·오류 보고서는 변경하지 않았습니다.

## 왜 추가했는가

[직전 실행](cs-001-skill-verification.md)은 Skill 네 파일을 모두 읽고도 편람을 확인하지 않았습니다. 숫자는 맞았지만 2026-1 WIKI와 Skill 지침을 근거로 들었습니다. Skill에 ‘원문을 대조하라’고 적는 것만으로는 그 절차를 따랐는지 확인할 수 없었습니다.

이번에는 어댑터에서 지정 판본의 원문 페이지 읽기와 인용을 요구하고, 도구 기록 및 실제 파일과 대조했습니다. WIKI와 질문, 직전 실행의 Skill 본문은 바꾸지 않았습니다.

## 바꾼 내용

- 편람 PDF·검색용 텍스트의 해시와 판본, 전체 페이지 수를 담은 메타데이터를 추가했습니다. 문항의 정답 페이지나 정답값은 넣지 않았습니다.
- `--source-contract`로 요청 판본과 파일 해시를 확인한 뒤 모델을 실행합니다.
- PDF Read 결과의 첫 페이지·페이지 수와 실제 전달된 이미지 블록 수를 기록합니다. 읽기 요청만으로 통과시키지 않습니다.
- `citations`의 판본·출처·페이지와 짧은 원문 인용을 검사합니다. 인용 페이지를 실제로 읽었어야 하며 문구도 해당 페이지에 있어야 합니다.
- 실패하면 `source-check.json`에 거절된 구조화 응답과 항목별 이유를 보존합니다. 자동 재시도는 하지 않습니다.

설정과 파일 형식은 [원문 인용 검사](../source-citations.md)에 정리했습니다. 판본 이름이 같다는 이유만으로 파일을 신뢰하지 않으며, 새 원문은 배포처와 추출본의 대응부터 확인해야 합니다.

## 같은 조건으로 유지한 것

| 항목 | 값 |

| 문항 | `CS-2026-2-001`, `pilots/cs-001-v2` |
| 모델·인증 | `claude-sonnet-4-6`, 기존 Claude Pro 로그인 |

| Skill | 직전 후보의 wrapper·본문·CLAUDE.md·PROJECT.md, 바이트 동일 |

| 질문·정답·rubric | 변경 없음, 이전 승인 재사용 없음 |

사용자가 추가 사용량을 껐다고 확인한 구독 경로로만 실행했습니다. API 키로 대체하지 않았습니다. A/B는 실행하지 않았고 C도 추가 호출하지 않았습니다.

어댑터의 지시와 인용 형식, 원문 메타데이터가 추가됐으므로 전체 실행 조건이 같은 실험은 아닙니다. `sources` 묶음의 해시도 메타데이터 추가로 바뀌었지만 기존 PDF·텍스트는 동일합니다. 이를 WIKI 또는 Skill 문구만의 개선 효과로 해석하지 않습니다.

Claude 프로세스는 정상 종료했고 추적도 완전했습니다. 시간 초과나 인증 실패가 아니라, **어댑터의 인용 검사에서 응답을 거절한 것**입니다.

거절된 답변의 `action`과 사실값 5개는 정답 초안과 모두 같았습니다. 인정 영역 2개, 이수 합계 9학점, 필요 영역 2개, 최소 학점 6, 충족 여부 true입니다. 이는 보관된 응답을 비교한 진단값이며, 정식 보고서의 `objective_pass`로 넣지 않았습니다. 보고서에는 error 1건, 품질 gate와 비교 결과는 `INCONCLUSIVE`로 남았습니다.

## 인용이 거절된 이유

| 인용 | 검사 결과 | 해석 |
| --- | --- | --- |
| PDF 52쪽의 균형교양 이수 요건 | 통과 | 실제 읽은 페이지에 같은 문구 존재 |
| PDF 53쪽의 2개 영역·6학점 설명 | 통과 | 실제 읽은 페이지에 같은 문구 존재 |
| 자연과과학 관련 표 인용 | 문구 불일치 | 영역·과목·제외 계열 셀을 이어 썼고 추출본에서는 연속된 문자열이 아님 |
| 문화와예술 관련 표 인용 | 문구 불일치 | 여러 행과 병합 셀을 하나의 문장처럼 재구성함 |
| 경제와사회 관련 표 인용 | 문구 불일치 | 표 셀 순서와 추출본의 텍스트 순서가 다름 |
| `학점 합계 6` | 길이 미달 | 실제 존재하지만 설정한 공백 제외 8자 기준보다 짧음 |

이 실패들을 ‘잘못된 편람을 인용했다’거나 ‘규정을 틀리게 해석했다’고 단정하면 안 됩니다. 이번 자동 검사는 **그대로 옮긴 연속 문구**를 요구했고, 표 셀을 재구성한 내용은 별도로 해석하지 않습니다. 마지막 항목은 실제 근거도 길이 기준 때문에 탈락할 수 있다는 검사 자체의 한계를 드러냈습니다. 통과 결과를 만들려고 실행 후 기준이나 응답을 바꾸지는 않았습니다.

다음에는 표 인용을 영역·과목·학점·제외 계열의 개별 문구로 나누고, 각 문구의 존재와 셀 간 관계를 구분해서 확인할 필요가 있습니다. 짧은 셀 값의 충분성도 길이만으로 판정하기 어렵습니다. 이 변경은 기존 실패를 보존한 새 검사 버전에서 검증해야 합니다.

## 사람이 확인할 부분

현재 검사로 확인한 것은 출처 파일, 판본, 전달 페이지, 인용 문구의 위치입니다. 해당 학번·학과에 규정을 올바르게 적용했는지, 필요한 예외를 빠뜨리지 않았는지는 사람 검토가 남아 있습니다. `semantic_support`는 항상 `requires_review`로 기록합니다.

답변에는 서비스 화면의 오류 원인을 특정할 수 없다는 설명이 있었지만, 문의처를 학사지원팀으로 안내한 부분은 제공 자료로 확인되지 않았습니다. 최소 6학점을 설명하면서 영역마다 고정된 3학점 규칙으로 일반화하지 않았는지도 검토해야 합니다. 이 항목들을 사람이 확인했다고 기록하지 않았습니다.

이번에는 정상 응답으로 채택되지 않아 `review-template`이 일반 답변 검토 항목을 만들지 않았습니다. 대신 로컬 `candidate-diagnostic.md`에 거절된 답변과 검사 결과를 모았습니다. 정답 초안과 이전 응답의 검토 상태도 그대로입니다.
